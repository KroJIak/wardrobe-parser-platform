# 05. Admin Sync Media

## `admin_users`

Учетные записи админов. Здесь лежит все, что нужно для входа, назначения роли и базового управления доступом.

| Атрибут | Тип значения | Пример | Что это и для чего |
|---|---|---|---|
| `id` | целое число | `3` | Внутренний id администратора. |
| `login` | строка | `andrey` | Логин для входа в админку. |
| `password_hash` | строка | `$argon2id$v=19$m=65536,t=3,p=4$...` | Хэш пароля, а не сам пароль. |
| `role_id` | целое число, nullable | `2` | Какая роль назначена пользователю. |
| `is_superuser` | логическое значение | `false` | Есть ли у пользователя полный доступ без ограничений роли. |
| `is_active` | логическое значение | `true` | Может ли пользователь сейчас входить в систему. |
| `last_login_at` | дата и время с часовым поясом, nullable | `2026-06-16 09:14:00+03` | Когда пользователь заходил последний раз. |
| `created_at` | дата и время с часовым поясом | `2026-02-01 12:00:00+03` | Когда пользователя создали. |
| `updated_at` | дата и время с часовым поясом | `2026-06-16 09:14:00+03` | Когда карточку пользователя меняли последний раз. |

## `admin_roles`

Роли админки как наборы полномочий. Они нужны, чтобы давать разным сотрудникам разный уровень доступа без ручной раздачи каждого права отдельно.

| Атрибут | Тип значения | Пример | Что это и для чего |
|---|---|---|---|
| `id` | целое число | `2` | Внутренний id роли. |
| `name` | строка | `Менеджер каталога` | Понятное имя роли в админке. |
| `description` | длинный текст, nullable | `Может редактировать товары, дизайнеров и фильтры.` | Короткое объяснение, что умеет эта роль. |
| `created_at` | дата и время с часовым поясом | `2026-02-01 11:40:00+03` | Когда роль создали. |
| `updated_at` | дата и время с часовым поясом | `2026-05-10 16:10:00+03` | Когда роль меняли последний раз. |

## `admin_role_permissions`

Конкретные права, входящие в роль. Эта таблица связывает роль с разрешенными действиями в системе.

| Атрибут | Тип значения | Пример | Что это и для чего |
|---|---|---|---|
| `role_id` | целое число | `2` | Для какой роли действует это право. |
| `permission_key` | строка | `products.edit` | Какое конкретное действие разрешено роли. |
| `created_at` | дата и время с часовым поясом | `2026-02-01 11:41:00+03` | Когда право привязали к роли. |

## `admin_sessions`

Сессии входа админов. Они позволяют безопасно хранить длительный вход, отзыв сессии и сроки жизни токенов.

| Атрибут | Тип значения | Пример | Что это и для чего |
|---|---|---|---|
| `id` | целое число | `91` | Внутренний id сессии администратора. |
| `admin_user_id` | целое число | `3` | Какому пользователю принадлежит сессия. |
| `refresh_token_hash` | строка | `a7ef3f3b1c2d...` | Хэш refresh-токена для продления входа. |
| `access_expires_at` | дата и время с часовым поясом | `2026-06-16 10:14:00+03` | Когда истекает текущий доступ. |
| `refresh_expires_at` | дата и время с часовым поясом | `2026-06-23 09:14:00+03` | Когда уже нельзя будет продлить сессию. |
| `revoked_at` | дата и время с часовым поясом, nullable | `NULL` | Когда сессию принудительно отозвали. |
| `last_used_at` | дата и время с часовым поясом | `2026-06-16 09:44:00+03` | Когда этой сессией пользовались последний раз. |
| `created_at` | дата и время с часовым поясом | `2026-06-16 09:14:00+03` | Когда сессию создали. |

## `image_assets`

Файлы, загруженные в систему вручную. Это общий реестр изображений, который потом используют товары, витрина и другие сущности.

| Атрибут           | Тип значения                            | Пример                               | Что это и для чего                                                              |
| ----------------- | --------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------- |
| `id`              | целое число                             | `912`                                | Внутренний id загруженного файла.                                               |
| **`storage_key`** | строка                                  | `products/2026/06/16/vest-front.jpg` | Внутренний путь файла в хранилище. Внешний URL backend собирает сам при ответе. |
| `mime_type`       | строка                                  | `image/jpeg`                         | Тип файла.                                                                      |
| `byte_size`       | целое число                             | `482311`                             | Размер файла в байтах.                                                          |
| `width_px`        | целое число, nullable                   | `1600`                               | Ширина картинки в пикселях.                                                     |
| `height_px`       | целое число, nullable                   | `2000`                               | Высота картинки в пикселях.                                                     |
| `checksum_sha256` | строка                                  | `5a2b1c8f...`                        | Контрольная сумма файла, чтобы ловить дубли и порчу.                            |
| `created_at`      | дата и время с часовым поясом           | `2026-06-16 09:20:00+03`             | Когда файл добавили в систему.                                                  |

## `showcase_settings`

Глобальные медиа-настройки главной страницы витрины. Здесь хранится полноэкранное hero-изображение без текста и другой контентной обвязки.

| Атрибут                    | Тип значения                  | Пример                   | Что это и для чего                                                       |
| -------------------------- | ----------------------------- | ------------------------ | ------------------------------------------------------------------------ |
| **`id`**                   | целое число                   | `1`                      | Id единственной строки настроек витрины.                                 |
| **`hero_image_asset_id`**  | целое число, nullable         | `912`                    | Какую загруженную картинку показывать на первом экране главной страницы. |
| **`created_at`**           | дата и время с часовым поясом | `2026-06-16 10:00:00+03` | Когда настройки создали.                                                 |
| **`updated_at`**           | дата и время с часовым поясом | `2026-06-16 10:30:00+03` | Когда настройки меняли последний раз.                                    |

## `showcase_carousel_images`

Фотографии карусели главной страницы. Каждая запись хранит одну картинку и ее порядок показа.

| Атрибут | Тип значения | Пример | Что это и для чего |
|---|---|---|---|
| **`id`** | целое число | `41` | Внутренний id картинки в карусели. |
| **`image_asset_id`** | целое число | `913` | Какую загруженную картинку использовать в карусели. |
| **`position`** | целое число | `1` | В каком порядке показывать картинку в карусели. |
| **`created_at`** | дата и время с часовым поясом | `2026-06-16 10:05:00+03` | Когда картинку добавили в карусель. |
| **`updated_at`** | дата и время с часовым поясом | `2026-06-16 10:30:00+03` | Когда запись меняли последний раз. |

## `sync_jobs`

Общие задачи синхронизации. Это верхний журнал запуска sync-процесса, чтобы админ видел причину старта, статус и общий итог.

| Атрибут                      | Тип значения                                                         | Пример                   | Что это и для чего                                          |
| ---------------------------- | -------------------------------------------------------------------- | ------------------------ | ----------------------------------------------------------- |
| **`id`**                         | целое число                                                          | `184`                    | Внутренний id общей задачи синхронизации.                   |
| **`trigger_kind`**               | строка из списка: `manual / scheduled / retry`                       | `manual`                 | Почему стартовал sync: вручную, по расписанию или повторно. |
| **`status`**                     | строка из списка: `queued / running / completed / failed / canceled` | `running`                | Текущее состояние общей синхронизации.                      |
| **`triggered_by_admin_user_id`** | целое число, nullable                                                | `3`                      | Кто запустил синхронизацию вручную.                         |
| **`created_at`**                 | дата и время с часовым поясом                                        | `2026-06-16 12:55:00+03` | Когда задачу создали.                                       |
| **`started_at`**                 | дата и время с часовым поясом, nullable                              | `2026-06-16 12:56:00+03` | Когда sync реально стартовал.                               |
| **`finished_at`**                | дата и время с часовым поясом, nullable                              | `NULL`                   | Когда sync закончился.                                      |
| **`total_sources`**              | целое число                                                          | `12`                     | Сколько источников нужно обработать.                        |
| **`processed_sources`**          | целое число                                                          | `5`                      | Сколько источников уже обработано.                          |
| **`products_seen`**              | целое число                                                          | `1840`                   | Сколько товаров пришло от service.                          |
| **`products_applied`**           | целое число                                                          | `1762`                   | Сколько товаров backend применил в БД.                      |
| **`error_message`**              | длинный текст, nullable                                              | `NULL`                   | Общая ошибка sync, если она была.                           |

## `sync_job_source_runs`

Прогоны синхронизации по конкретному источнику внутри общей задачи. Они нужны, чтобы отдельно видеть результат по каждому source, а не только общий sync.

| Атрибут | Тип значения | Пример | Что это и для чего |
|---|---|---|---|
| **`id`** | целое число | `881` | Внутренний id запуска по одному источнику. |
| **`sync_job_id`** | целое число | `184` | К какой общей синхронизации относится запуск. |
| **`source_id`** | целое число | `12` | Какой именно источник обрабатывали. |
| **`status`** | строка из списка: `queued / running / completed / failed / skipped` | `completed` | Чем закончился прогон по этому источнику. |
| **`started_at`** | дата и время с часовым поясом, nullable | `2026-06-16 12:56:10+03` | Когда началась обработка источника. |
| **`finished_at`** | дата и время с часовым поясом, nullable | `2026-06-16 12:58:44+03` | Когда обработка закончилась. |
| **`products_received`** | целое число | `243` | Сколько товаров service отдал по этому источнику. |
| **`products_applied`** | целое число | `239` | Сколько товаров backend записал по этому источнику. |
| **`failed_products`** | целое число | `4` | Сколько товаров не удалось применить. |
| **`error_code`** | строка, nullable | `storefront_password_gate` | Короткий машинный код ошибки этого прогона по источнику. |
| **`error_message`** | длинный текст, nullable | `NULL` | Ошибка прогона по источнику, если она была. |

## `sync_applied_batches`

Журнал уже примененных батчей синхронизации. Он защищает от повторной записи одного и того же входящего пакета данных.

| Атрибут                  | Тип значения                  | Пример                                | Что это и для чего                                    |
| ------------------------ | ----------------------------- | ------------------------------------- | ----------------------------------------------------- |
| **`id`**                 | целое число                   | `5102`                                | Внутренний id примененного батча.                     |
| **`source_run_id`**      | целое число                   | `881`                                 | В какой прогон по источнику был применен этот батч.   |
| **`batch_key`**          | строка                        | `misssixty-2026-06-16T12:56:13Z-0003` | Уникальный ключ батча, чтобы не применить его дважды. |
| **`applied_at`**         | дата и время с часовым поясом | `2026-06-16 12:57:02+03`              | Когда backend записал этот батч в БД.                 |
