# 06. Dedup

## `product_dedup_decisions`

Журнал решений по дублям товаров. Здесь фиксируется сам факт merge или reject.

| Атрибут                  | Тип значения                       | Пример                   | Что это и для чего                                       |
| ------------------------ | ---------------------------------- | ------------------------ | -------------------------------------------------------- |
| `id`                     | целое число                        | `74`                     | Внутренний id решения по дублям.                         |
| **`decision_kind`**      | строка из списка: `reject / merge` | `merge`                  | Какое действие админ принял по найденным дублям.         |
| **`created_product_id`** | целое число, nullable              | `903`                    | Какой новый витринный товар появился в результате merge. |
| `created_at`             | дата и время с часовым поясом      | `2026-06-14 15:32:00+03` | Когда решение создали.                                   |

## `product_dedup_decision_members`

Входные товары конкретного dedup-решения. Результирующий товар отдельно хранится в `product_dedup_decisions.created_product_id`, поэтому дублировать его роль здесь не нужно.

| Атрибут | Тип значения | Пример | Что это и для чего |
|---|---|---|---|
| `decision_id` | целое число | `74` | К какому решению относится эта строка. |
| `product_id` | целое число | `501` | Какой товар участвует в решении. |
